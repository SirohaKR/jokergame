01. 제품 방향과 현재 범위

가제 라스트 원. 트럼프 도둑잡기의 간단한 규칙에 캐릭터와 뽑기 시점 연출을 결합한 4인 카드 게임입니다. 친구끼리 창모드로 플레이하며 내 차례나 결과를 확인하는 이용 흐름을 전제로 합니다. 작혼의 좌석·프로필 구도와 아스트랄 파티의 캐릭터 중심 반응을 참고하되 제공된 스탠딩과 자체 UI만 사용합니다.

현재 결과물은 한 세트를 끝까지 진행할 수 있는 로컬 AI 프로토타입입니다. 온라인 멀티·계정·DB 연결·스킬·여러 세트 합산·랭크 및 재화 지급은 구현하지 않았습니다. DB/API/배포 구성은 후속 개발을 위한 설계이며 이미 운영 중인 서버를 뜻하지 않습니다.

02. 확정 규칙과 상태 전이

일반 트럼프 52장(13등급 × 4무늬)에 조커 한 장을 추가합니다. 4명에게 나누고 처음 받은 같은 등급 두 장은 자동 제거합니다. 조커는 페어가 되지 않습니다. 매 차례 오른쪽의 생존 플레이어에게서 한 장을 뽑습니다. 빈손 플레이어는 건너뜁니다.

행동 선택
20초→ 카드 선택
20초→ 카드 재클릭 확정→ 결과 연출
3초 · 타이머 정지→ 페어 정리
20초→ 다음 턴 / 종료
  • 한 번 클릭하면 선택, 같은 카드 재클릭 시 뽑기 확정입니다. 다른 카드를 선택하면 선택 위치가 바뀝니다. 현재 프로토타입은 유효한 선택 행동마다 20초를 다시 부여합니다.
  • 행동 선택 시간 초과는 뽑기로 이동, 카드 선택 시간 초과는 선택한 카드(없으면 무작위) 확정, 페어 미처리는 자동 버리기입니다.
  • B가 A의 마지막 카드를 뽑으면 A의 종료 순위를 먼저 확정합니다. B는 카드를 받은 뒤 페어 제거 단계가 끝나야 빈손으로 인정합니다.
  • 조커를 마지막까지 가진 한 명만 패배합니다. 나머지 세 명은 모두 승리하며, 종료 순서에 따라 +1000 / +500 / 0 / -500점을 받습니다.
  • 세트 점수는 음수가 가능합니다. 랭크 점수와 재화는 별도 값입니다. 여러 세트 합계로 최종 1~4등을 결정한 뒤 지급합니다.
  • 초기 페어 제거 직후 여러 빈손이 생기는 예외는 시작 좌석부터 진행 방향 순서로 확정하는 임시 기준을 사용합니다. 최종 기획 승인 때 재확인합니다.

시점과 공개 범위

역할선택 중결과
A: 뽑는 사람B의 뒷면 카드, 선택 위치뽑은 카드와 두 사람 반응
B: 뽑히는 사람자기 앞면 카드와 A의 선택 위치. 손패 정렬 잠금뽑힌 카드와 두 사람 반응
C·D: 나머지테이블 대기, 자기 손패 정렬 가능계속 테이블 대기. 카드 정체·당사자 반응 숨김

선택 중에는 카드 정체를 드러내는 표정 반응이 없습니다. 조커를 뽑았을 때만 당사자에게 웃음/충격 연출을 사용합니다. 현재는 정지 스탠딩이므로 대사·이동·효과음으로 대체했습니다. 자발적으로 보내는 공개 이모티콘은 정보 노출을 별도로 제한하지 않습니다. 이모티콘 표시 2초, 재사용 대기 3초입니다.

03. 화면과 배치 기준

PC 가로형 1440×810 논리 좌표를 기준으로 화면에 맞게 축소합니다. 프로필은 정사각형 얼굴 + 아래 이름입니다. 사람은 닉네임, 봇은 캐릭터명을 표시합니다. 상대 패는 텍스트 장수가 아닌 실제 개수의 뒷면 카드입니다.

  • 중앙 버리는 구역: x=420, y=355, 너비=600, 높이=190. 가로 중심=720, 세로 중심=450.
  • 상단 C: 얼굴/이름/카드 묶음이 가로 중심 720에 정렬. 카드 아래쪽은 중앙 구역 위쪽과 분리합니다.
  • 좌우 D/B: 얼굴·이름과 가로로 눕힌 세로 카드 묶음이 세로 중심 450을 기준으로 정렬됩니다. 실제 카드 영역은 중앙 버리는 구역 바깥입니다.
  • 카드 수가 늘면 펼침 간격을 줄입니다. 중앙 구역과 교차하지 않도록 좌석별 고정 영역을 유지합니다.
  • 나의 앞면 손패는 하단. 드래그로 정렬하고, 페어 정리 시 해당 카드만 강조합니다. 종료한 사람은 관전하며 비공개 패는 볼 수 없습니다.

영속 데이터

현재 frontend는 화면(app.js), 규칙(game.js), 캐릭터·설정(data.js), 스타일(styles.css)로 분리했습니다. backend/server.mjs는 HTTP 파일 제공과 상태 확인만 담당합니다. 게임 규칙은 DOM·타이머·저장소 의존성이 없는 함수로 구현하여 이후 서버에서 같은 규칙을 실행할 수 있게 했습니다.

온라인 단계에는 브라우저가 의도만 제출하고 서버가 덱/손패/시간/순위/보상을 결정합니다. 프론트는 서버 이벤트를 표시합니다. 서버는 참가자별 상태를 투영하여 타인의 앞면 카드·내부 카드 ID·덱 시드·난수 상태를 보내지 않습니다. 현재 로컬 AI전 전체 상태는 개발자 도구에서 볼 수 있으므로 온라인 보안 구현으로 간주하지 않습니다.

영역책임
프론트입력, 화면 전환, 카드/캐릭터 연출, 보이는 정보만 렌더링, 접속 상태와 복구 UI
백엔드인증, 방/좌석 권한, 직렬화된 게임 행동, 서버 타이머, 비공개 상태 분리, 정산 트랜잭션
DB계정/소유품/호감도/결과/보상 원장/복구 스냅샷. 접속자에게 직접 공개하지 않음
자산현재 frontend/assets 로컬 정적 파일. 이미지 파일명과 마스터 ID를 분리하고 버전 관리

게임 처리 트랜잭션

  1. 해당 세트 스냅샷 행을 SELECT FOR UPDATE로 잠그고, 요청자가 행동 가능한 좌석인지 검사합니다.
  2. commandId 중복, expectedRevision, 타이머 만료, 카드 선택 토큰 유효성을 검증합니다.
  3. 행동을 적용하여 revision 증가, 이벤트 저장, 스냅샷 갱신을 한 트랜잭션으로 커밋합니다.
  4. 커밋 후 참가자별로 투영된 이벤트를 전송합니다. 전송 실패 시 같은 sequence부터 재전송하며 UI는 중복 제거합니다.
  5. 세트 종료 시 set_results와 합산 점수를 함께 기록합니다. 매치 종료 전에는 랭크/재화를 지급하지 않습니다.

05. 시놀로지 NAS 배포 계획

NAS 모델·CPU 아키텍처·메모리·DSM 버전은 아직 전달받지 않았습니다. Container Manager 지원 여부를 확인한 뒤 이미지 아키텍처와 리소스 제한을 확정합니다. 모든 시놀로지 모델에서 같은 방식으로 실행된다고 가정하지 않습니다.

구성계획

온라인 확장frontend 정적 서비스, backend API/WS, PostgreSQL을 별도 서비스로 분리. 현재 Compose에는 미포함

DB 네트워크컨테이너 내부망 전용. PostgreSQL 5432 인터넷 공개 금지. 운영 DB 계정 최소 권한

06. DB 상세 설계

제안 DB는 PostgreSQL입니다. 아래는 모든 필드의 의미와 DDL 제약을 정리한 데이터 사전입니다. 전체 schema.sql에 PK/FK/UNIQUE/CHECK와 조회 인덱스를 제공합니다. 스키마는 아직 DB에서 실행하지 않은 설계 초안입니다.

관계 구조

users ─┬─ identities / refresh_sessions / user_settings / wallets
       ├─ user_characters ─ user_cosmetics ─ user_equipment
       ├─ match_players ─ matches ─ game_sets ─ set_results
       │                                  ├─ set_snapshots (server only)
       │                                  └─ set_events (restricted)
       └─ reward_grants / wallet_ledger / idempotency_keys
characters ─ cosmetics

시각은 모두 UTC timestamptz, 금액은 정수입니다. 삭제는 기본 FK RESTRICT로 기록의 무결성을 유지합니다. 서비스에서 updated_at을 갱신합니다. assets의 파일 경로는 허용된 정적 자산 경로만 받도록 검증합니다. 개인정보 보존 기간·탈퇴 익명화는 출시 전에 별도 확정합니다.

정산·구매·중복 방지

  • 매치 종료: matches 잠금 → 종료 여부 검사 → 결과 합산/동점 정책 적용 → wallets 행 잠금 → reward_grants 삽입 → wallet_ledger 기록 → 잔액 업데이트 → finished 상태를 원자적으로 커밋합니다.
  • reward_grants의 UNIQUE(match_id,user_id), 원장의 reference_key로 중복 지급을 차단합니다. 이미 지급된 요청은 기존 결과를 반환합니다.
  • 랭크가 0 미만이 되지 않도록 반영 후 잔액을 계산하고 실제 delta만 원장에 기록합니다. 세트 점수 -500은 별도로 보존됩니다.
  • 선물 구매: 서버 상품 가격 확인 → 소유 캐릭터 확인 → 지갑 잠금 → 잔액 확인 → 차감/원장/호감도/해금/멱등 응답을 한 트랜잭션 처리합니다.
  • 스킨 적용은 보유 FK 외에 cosmetics.kind='skin'을 서비스에서 검증합니다. 세트 결과는 종료 시 4행이 존재하는지 검증합니다.
  • 재접속 스냅샷에는 현재 phase, deadline, actor, revision, 각 손패, 종료 순서, 미처리 draw 결과, RNG 상태를 보관합니다. JSON 구조 버전을 별도 포함합니다.
  • set_events는 재연결/분쟁 분석에 사용하되 카드 비공개 정보를 일반 로그에 기록하지 않습니다. 완료 경기 이벤트는 보존 기간 후 정리합니다.
  • 마이그레이션은 순번 파일로 관리합니다. 파괴적 변경은 신규 필드 추가 → 백필 → 읽기 전환 → 구 필드 제거의 단계로 나눕니다.

07. REST · Swagger / OpenAPI

Swagger는 API 자체의 통신 방식이 아니라 OpenAPI 문서를 표시하고 테스트하는 도구입니다. Swagger UI와 OpenAPI 3.0.3 JSON을 함께 제공합니다. GET /api/health만 현재 구현되었으며, 나머지는 501을 반환하는 후속 설계입니다. Swagger UI의 요청 실행 기능은 현재 비활성화했습니다.

API목적 / 권한

온라인 인증은 HttpOnly/Secure/SameSite 쿠키와 변경 요청 CSRF 토큰을 기본 설계로 둡니다. 공급자/회원가입 방식은 미정이며 실제 로그인 기능은 없습니다. 요청 중복 시 Idempotency-Key와 본문 해시를 비교합니다. 일반 오류 형식은 code/message/requestId입니다. 400 입력 오류, 401 인증, 403 권한, 404 없음, 409 상태 충돌, 429 제한을 구분합니다.

현재단일 세트 AI 프로토타입53장 보존, 순위 중복 없음, 한 조커만 남아 종료, 화면 경계 비충돌
다음 1연출 개선 / 스킬 소수 실험웃음·충격 표정 자산, 손 이동, 스킬 사용/잠금/타이머 검증
다음 2서버 판정 + 4인 비공개 방3개 이상의 브라우저로 정보 격리·재접속·중복 명령·시간초과 검증
다음 3여러 세트와 DB 정산동점 규칙 확정, 중복 보상 없음, 장애 후 복구 일관성
다음 4호감도·스킨·상점동시 구매 잔액 음수 없음, 소유하지 않은 자산 적용 차단
유니티 판단앱·스팀 배포/고급 연출 필요 시룰·자산·프로토콜 재사용, 웹 화면 코드의 직접 이식은 전제하지 않음

확정이 필요한 항목

  • NAS 모델/DSM 버전/CPU/메모리, 도메인, 예상 동시 방 수.
  • 매치당 세트 수, 합산 동점 순위, 시작 좌석 교대 규칙.
  • 온라인 중도 이탈/재접속 유예, 방장 이탈, 서버 재시작 시 세트 정책.
  • 반복 선택의 20초 재갱신 횟수, 첫 분배 빈손 동시 발생 순위.
  • 캐릭터 최종 이름/표정/스킬, 랭크·재화·호감도 수치.

검증 기록

덱 구성, 최초 페어 제거, 제공자 종료 우선, 잘못된 행동 거부, 상태 불변성, 비공개 뷰, 드래그 순열 검증을 자동 테스트했습니다. 1,000개 시드의 전체 게임에서 카드 53장 보존·순위 중복 없음·마지막 조커 단독 보유를 확인했습니다. headless 브라우저에서 메인→로비→테이블→뽑기→결과→세트 종료와 중앙 카드 비충돌을 확인했습니다. NAS 실제 배포·PostgreSQL DDL 실행·온라인 부하 테스트는 아직 하지 않았습니다.

09. 자산과 전달 파일

v0.3 모바일 플레이: 600px 이하에서는 세로 테이블 배치 사용. 손패와 뽑기 패는 가로 스크롤하며, 손패의 순서 변경 버튼으로 카드 선택 후 좌우 이동이 가능합니다. 대기자는 다른 사람의 결과 연출·페어 처리 중에도 정렬 가능. 뽑기 당사자와 자신의 페어 처리 중에는 정렬을 잠급니다. 페이지 및 카드 목록의 스크롤은 화면 갱신 후 유지됩니다.

v0.2 추가: 원본 캐릭터를 참고한 투명 SD 이모티콘 16종(4명 × 웃음·당황·인사·의심). 메인 모아보기, 공개 선택 전송(2초 표시/3초 쿨다운), 조커 제공자 웃음·수령자 당황 및 결과 표정을 구현했습니다. 자동 반응과 조커 효과음은 두 당사자에게만 적용합니다. assets/emotes/manifest.json에 생성 프롬프트를 기록했습니다.

사용자가 제공한 WebP 4장의 흰 배경을 built-in image_gen 도구로 제거하고 PNG 알파 채널을 보존했습니다. 원본은 수정하지 않았습니다. 캐릭터 얼굴은 별도 그림 생성 없이 CSS 배경 위치로 크롭합니다. 배경 제거는 생성형 편집이므로 원본과의 픽셀 단위 동일성을 보장하지 않습니다.
